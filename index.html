SOP-03 Google Drive rclone 마운트 중단 / 크래시루프 복구

마운트포인트 충돌(`directory already mounted`)이나 고아 프로세스로 인한 systemd 활성화 실패 시 강제 클린업 후 재시작합니다.

BASH 
# 1. systemd 서비스 중지 및 고아 rclone PID 정리
systemctl --user stop rclone-gdrive.service nohmi-wiki-mount.service
killall -9 rclone 2>/dev/null || true

# 2. 지저분한 FUSE 마운트 강제 해제 (Lazy unmount)
fusermount3 -uz ~/gdrive 2>/dev/null || true
fusermount3 -uz ~/nohmi_llmwiki 2>/dev/null || true

# 3. systemd 실패 상태 초기화 및 서비스 재기동
systemctl --user reset-failed
systemctl --user start rclone-gdrive.service nohmi-wiki-mount.service

# 4. 마운트 무결성 확인
ls -ld ~/gdrive/work/SecondBrain
ls -ld ~/nohmi_llmwiki
SOP-04 JKNAS NFS 마운트 및 DSM 권한 (쓰기 거부) 조치

JKNAS는 DSM 6.1.5로 NFSv3만 지원하며 Squash="모든 사용자를 admin 매핑" 설정이 필수입니다. 클라이언트에서 쓰기가 거부되면 NAS에 직접 SSH로 접속해 소유권을 변경합니다.

BASH 
# N100에서 수동 마운트
sudo mount -t nfs -o vers=3 192.168.1.219:/volume3/HDD2 /mnt/jknas/HDD2
sudo mount -t nfs -o vers=3 192.168.1.219:/volume3/music-library-v2 /home/ttolmany/nas/music-library-v2

# 쓰기 거부 시: JKNAS에 SSH 접속 후 소유권 재설정
ssh admin@192.168.1.219 "sudo chown -R admin:users /volume3/HDD2 /volume3/music-library-v2"
SOP-05 CPU 2.5GHz 클럭 제한 및 발열 스로틀링 점검

Jellyfin 트랜스코딩 등 고부하 시 89°C 치솟음 방지를 위해 4개 코어 클럭을 2.5GHz로 제한하고 온도를 점검합니다.

BASH 
# 1. 온도 및 써멀 스로틀 카운트 확인
sensors
cat /sys/devices/system/cpu/cpu0/thermal_throttle/package_throttle_count

# 2. 클럭 상한 확인 (2500000 = 2.5GHz)
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_max_freq

# 3. 풀려있을 경우 즉시 2.5GHz 재적용
sudo cpupower frequency-set -u 2500000
